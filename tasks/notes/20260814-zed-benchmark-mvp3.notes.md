## Applied hardening

- Checkout identity requires the exact approved integration `HEAD`.
- Checkout cleanliness rejects tracked and non-ignored untracked changes while
  permitting ignored runtime/cache state such as uv `.venv`.
- Admission predicates are reused by receipt read validation.
- Receipt reads enforce exact pin, source SHA, namespace/model syntax,
  task/concurrency bounds, exact resource policy, and timestamp invariants.
- Receipt phases are prototype-safe.
- Receipt transitions are serialized.
- Submission ambiguity preserves the exact generated run ID and is never
  automatically retried.
- Successful launch acceptance must prove the expected namespace, experiment,
  run ID, and controller-spawn evidence; malformed acceptance is uncertain.
- Fetch/report evidence is confined to the exact ignored run directory.
- Report JSON is bound to the exact requested `job_dir`.
- The planning package points to production source as executable authority.

## Acceptance state

### T3

Blocked until:

- package-local `archctx` readiness is proven;
- capability resolution succeeds;
- provider-native planning succeeds;
- projection is generated by the configured provider;
- strict architecture synchronization passes.

Generated architecture Markdown must not be hand-edited.

### T13

Incomplete until every required final-candidate command succeeds.

A failing root suite is not treated as passing merely because failures appear
unrelated. Any accepted baseline exception requires an explicit approved-plan
change identifying exact stable failures.

### T14

Not ordinary CI.

Requires fresh operator approval immediately before the paid run, dedicated
credentials, known budget/quota, one task, one concurrent sandbox, manual doctor
preflight, and confirmation that the required deployment already exists.

An uncertain submission is reconciled by its existing run ID. Never submit a
replacement automatically.

### T15

Requires final review, execution-boundary verification, contract-worktree
finish, and archival of durable review/plan evidence.

## Definition of done

MVP 3 is complete only after T3, T13, T14, and T15 are satisfied and the final
accepted commit SHA replaces the placeholder above.
